# 5W1H Thought — Output Format

Structured problem-scoping across Who, What, When, Where, Why, and How.

## JSON Schema

```json
{
  "mode": "5w1h",
  "who": "<person(s)/team(s) involved, string or array>",
  "what": "<what happened/is being scoped, string or array>",
  "when": "<time/timeframe, string or array>",
  "where": "<location/system/scope, string or array>",
  "why": "<reason/root driver, string or array>",
  "how": "<mechanism/method, string or array>",
  "summary": "<optional one-paragraph synthesis>"
}
```

## Required Fields

- `mode` — always `"5w1h"`
- `who` — the person(s), team(s), or system(s) involved
- `what` — what happened, or what is being scoped
- `when` — the time or timeframe
- `where` — the location, system, or scope
- `why` — the reason or root driver, as currently understood
- `how` — the mechanism or method by which `what` occurred

Each of `who`/`what`/`when`/`where`/`why`/`how` accepts either a single string or an array of strings — use an array when a dimension genuinely has multiple independent facts (e.g., `who` naming both a person and an affected user population).

## Optional Fields

- `summary` — a short prose synthesis pulling the six dimensions together into one paragraph. Useful when the six fields alone would leave the reader to do the synthesis themselves.

## When to Use 5W1H

5W1H is a **scoping** tool, not a root-cause or strategy tool — use it to fully define a problem *before* applying `fivewhys`, `fishbone`, or any other analysis. It answers "what exactly are we dealing with?" not "why did it happen?" (though `why` is one of the six dimensions, it captures the *currently understood* reason, not a drilled-down root cause — for that, chain into `fivewhys`).

## Verification Checklist

Before emitting, verify:
- `mode` is exactly `"5w1h"`
- All six of `who`, `what`, `when`, `where`, `why`, `how` are present and non-empty — per the "fill every field or say 'none identified'" rule in `skills/think-frameworks/SKILL.md`, a field that is genuinely unknown should contain the literal string `"unknown"` or `"not yet determined"`, never be omitted
- Array-valued fields contain genuinely distinct facts, not the same fact restated
- `why` states the currently-understood driver, not a fabricated root cause the evidence doesn't support yet

## Worked Example

Input: "Scope this incident: checkout API returned 500s for card payments for about 40 minutes this morning."

Output:

```json
{
  "mode": "5w1h",
  "who": ["On-call engineer Priya Patel", "Payments platform team", "~1,200 affected checkout sessions"],
  "what": "Checkout API returned HTTP 500 for all card payments, blocking order completion",
  "when": "2026-07-06 14:32 UTC through 15:10 UTC (38 minutes)",
  "where": "us-east-1 region, checkout-api service calling the payment-gateway microservice",
  "why": ["A scheduled credential-rotation deploy at 14:30 UTC rotated the payment gateway API key without invalidating checkout-api's cached copy of the old key"],
  "how": ["The rotation deploy updated payment-gateway's accepted key set, but checkout-api kept using its cached (now-invalid) key, so every gateway call returned 401, which checkout-api's error handler mapped to a generic 500 for the caller"],
  "summary": "A credential-rotation deploy at 14:30 UTC broke checkout for 38 minutes because checkout-api's cached gateway secret was not invalidated in lockstep with the rotation; incident scoped to us-east-1 card payments only."
}
```

This fully scopes the incident across all six dimensions before any root-cause drilling begins. Note that `why` here is the immediate mechanical reason (cache not invalidated), not yet a drilled-down root cause of *why the invalidation process is missing* — that deeper question belongs to `fivewhys`.
