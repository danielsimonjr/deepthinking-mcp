**Summary for humans:** The right algorithm is a **min-heap of fixed size K=100**, scanned once over N=1,000,000 items. The heap's minimum acts as a rising admission threshold — each item either beats the current weakest top-K member (replace it, O(log K)) or doesn't (discard, O(1)). This yields **O(N log K) ≈ 6.64M operations** versus **O(N log N) ≈ 19.93M** for a full sort — about 3× fewer comparisons — while using only **O(K) = ~6.4 KB of memory** instead of O(N), which fits entirely in L1 cache for excellent practical throughput. Every alternative either violates the streaming constraint (Quickselect, heapify-all), incurs worse asymptotic complexity (full sort), or matches the heap's bounds with worse constant factors (Red-Black BST).
