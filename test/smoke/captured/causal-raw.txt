---

**Both the eviction policy change and the memory limit change are genuine co-causes of the p99 latency spike** — the memory limit change is not merely a confounder, it has two independent causal paths to latency (cache capacity reduction and OS swapping). The true confounder is the **deployment event itself**, which introduced both changes simultaneously and makes naive attribution impossible without a controlled isolation experiment.

To determine their relative contributions, the cleanest next step is a **split revert experiment**: first restore only the eviction policy (keeping new memory limit) and observe whether latency partially recovers, then restore only the memory limit (keeping new eviction policy) and observe the same — partial recoveries on each arm confirm both are active causes, and their magnitudes tell you which dominates. If the memory limit revert alone resolves nearly all of the spike, the eviction policy change contributed little; if the eviction policy revert resolves most of it, the policy change was the dominant path.
