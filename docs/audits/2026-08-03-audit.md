# deepthinking-mcp — Audit Report

**Date:** 2026-08-03 · **Version audited:** 9.2.0 (npm `deepthinking-mcp@9.2.0`, plugin `deepthinking-mcp` 9.2.0)
**Method:** four parallel specialist auditors (performance · security · maintainability · supportability), each read-only, each with a pre-launch machine baseline and a post-return cleanup gate. **Every load-bearing finding below was re-verified by the session lead against the repo before inclusion.** Three agent claims failed that verification and are corrected in place — see [Corrections](#corrections-to-the-agents).

---

## 1. Executive summary

deepthinking-mcp is a **structurally sound, unusually well-tested project with a documentation and enforcement problem**. The architecture (service layer → `ModeHandlerRegistry` strategy dispatch → typed thought union) is coherent and verified accurate. The error hierarchy, the export sandbox, the prototype-pollution guard, and the Python render scripts are all genuinely well built — several are *better* than their documentation implies.

The risk is concentrated in three places:

1. **Config knobs that are documented but dead.** `MCP_MAX_SESSIONS` and `MCP_SESSION_TIMEOUT_MS` are parsed, validated, and then never read. The real session cap is a hardcoded `1000` — **10× the documented default of 100**. An operator tuning for a memory-constrained deployment is silently ignored.
2. **Input bounding applied in exactly one place.** Sanitization runs only in `SessionManager`; **zero** of the 37 mode handlers call it. Per-session thought arrays have no cap at all.
3. **Gates that don't gate.** The 186-file Python suite has *zero* CI invocation. The coverage check emits `::warning::` instead of failing. `npm run lint` has no `--max-warnings`, so 357 `any` warnings can grow forever. The version-drift guard has a regex blind spot for the one file that is currently stale.

**The dominant theme: this project's automation reports success more readily than it earns it.** That is also the cheapest class of problem to fix — most items below are S-effort.

## 2. Findings by severity

### 🔴 HIGH

#### H-1 · GitHub Release notes tell users to install a package that does not exist
**Evidence:** `.github/workflows/release.yml:121`
```
npm install @anthropic/deepthinking-mcp@${{ steps.get_version.outputs.version }}
```
`https://registry.npmjs.org/@anthropic%2Fdeepthinking-mcp` → **404**. The real package is unscoped `deepthinking-mcp`. This is copy-paste debris from an upstream template, never customised.
**Impact:** every GitHub Release page's Installation section is wrong. This is the single most user-visible defect found.
**Fix:** one-line change to `npm install deepthinking-mcp@...`. **Effort: S.**

#### H-2 · Unbounded free-text input across all 34 modes
**Evidence (verified):** sanitization is referenced only in `src/utils/sanitization.ts` (definition) and `src/session/manager.ts` (6 call sites). Grep across `src/modes/handlers/` + `src/services/ThoughtFactory.ts` for any sanitizer → **0 hits**. In `src/tools/schemas/`: **233** `z.string()` occurrences vs **14** `.max(` occurrences.
`MAX_LENGTHS` exists (`THOUGHT_CONTENT: 100000`, `DESCRIPTION: 10000`) but is applied *only* on the `addThought` path.
**PoC (agent, live):** `deepthinking_probabilistic` with a 5 MB `hypotheses[0].description` and a 50,000-element `evidence` array was accepted and stored unmodified.
**Impact:** memory-exhaustion DoS bounded only by the MCP transport's 10 MB per-message ceiling.
**Fix:** apply the existing `MAX_LENGTHS` pattern (or zod `.max()`) uniformly across `src/tools/schemas/modes/*.ts`. **Effort: M.**

#### H-3 · Per-session thought arrays have no cap; `maxThoughtsInMemory` / `compressionThreshold` are aspirational
**Evidence:** `src/session/manager.ts` `DEFAULT_CONFIG` declares `maxThoughtsInMemory: 1000`, `compressionThreshold: 500`. `addThought()` does `session.thoughts.push(thought)` with no cap check; no compression/truncation logic exists anywhere in `src/session/`.
**Impact:** a single long-running session grows without backpressure. Combined with H-2, this is the actual memory-growth vector (not session count — see [C-2](#corrections-to-the-agents)).
**Fix:** enforce the fields, **or** delete them and document the unbounded behaviour honestly. Either is defensible; the current mismatch is not. **Effort: M.**

#### H-4 · The 186-file Python test suite has zero CI enforcement
**Evidence (verified):** `.github/workflows/*.yml` references to `pytest` / `harness.py` / `test_*.py` → **0**. And `pytest test --collect-only` collects **1 of 6** files, because five expose `check_*`/`main()` rather than pytest-shaped `test_*` functions.
**Impact:** a double blind spot. The scripts are good and *do* catch real drift when run by hand — but nothing runs them, and the obvious command to run them silently validates ~1% of the suite while exiting 0.
**Fix:** add a CI step invoking each script directly (they already return correct exit codes):
`python test/test_artifact_consistency.py && ... && python test/harness.py`. **Effort: S.**

#### H-5 · `npm run docs:deps` has been broken for months
**Evidence (verified):** `package.json` → `npx tsx tools/create-dependency-graph.ts`; that path **does not exist**. The real file is `tools/create-dependency-graph/create-dependency-graph.ts` (one level deeper). A second latent break: `import yaml from 'js-yaml'` fails under js-yaml 5.2.2 ESM — Dependabot bumped it (`0a6085b`) and nobody noticed the tool stopped running.
**Corroboration:** committed `docs/architecture/DEPENDENCY_GRAPH.md` says *Last Updated 2025-12-31* — predating the entire 9.2.0 merge, and un-regenerable via the documented command.
**Fix:** correct the path; patch the import to `import * as yamlNs from 'js-yaml'; const yaml = yamlNs.default ?? yamlNs;`. **Effort: S.**

### 🟠 MEDIUM

#### M-1 · Documented session cap is dead; real cap is 10× higher and unconfigurable
**Evidence (verified):** `maxActiveSessions` appears in `src/config/index.ts` only — line 25 (type), 68 (env parse, default 100), 137–138 (validation). **Zero** consumers elsewhere. `src/session/manager.ts:150` hardcodes `maxSize: 1000`.
**Impact:** `MCP_MAX_SESSIONS` is documented in README and CLAUDE.md and does nothing. Actual ceiling is always 1000 sessions (code comment estimates ~10–50 MB). Same for `MCP_SESSION_TIMEOUT_MS` — no expiry logic exists.
**Fix:** thread `getConfig().maxActiveSessions` into the `SessionManager` LRU config. **Effort: S.**

#### M-2 · `deleteSession()` leaks meta-monitoring state
**Evidence (verified):** `clearMetaSession` is defined at `src/session/manager.ts:947` and called at exactly **one** site — line 169, inside the LRU `onEvict` callback. `deleteSession()` never calls it, so `sessionHistory`, `currentStrategies`, and `modeTransitions` retain entries for every explicitly-deleted session, permanently.
**Fix:** add `this.clearMetaSession(sessionId)` to `deleteSession()`. **Effort: S (~15 min).**

#### M-3 · Nine live environment variables are undocumented
**Evidence (verified):** `src/config/index.ts` performs 14 `process.env` reads (15 across `src/`); README and CLAUDE.md document 6.
Undocumented but live: `MCP_MAX_THOUGHTS`, `MCP_COMPRESSION_THRESHOLD`, `MCP_MAX_CONTENT_LENGTH`, `MCP_VALIDATION_TOLERANCE`, `MCP_ENABLE_VALIDATION_CACHE`, `MCP_VALIDATION_CACHE_SIZE`, `MCP_ENABLE_PERSISTENCE`, `MCP_PERSISTENCE_DIR`, `MCP_ENABLE_PERF_METRICS`.
**Impact:** a user hitting a content-length or thought-count ceiling has no documented way to find the knob.
**Fix:** extend the env table. **Effort: S.** *(Note the interaction with M-1/H-3: several of these knobs are also dead. Document what is real, delete what is not.)*

#### M-4 · Coverage and lint gates are decorative
**Evidence (verified):**
- `.github/workflows/coverage.yml:179` → `echo "::warning::Code coverage ($COVERAGE%) is below 60% threshold"` — an annotation, never `exit 1`. The same file claims an **80%** threshold at line 117 while checking **60%** at line 179.
- `package.json` lint script is bare `eslint src/` with no `--max-warnings`; `eslint.config.js:21` sets `'@typescript-eslint/no-explicit-any': 'warn'`. Current state: **0 errors, 357 warnings**.
**Impact:** coverage (58.1% lines / 52.84% branches) and `any`-creep can both drift indefinitely with CI green. 17 files sit at **0%** coverage — including the validators for all five modes CLAUDE.md calls "Core" (sequential, shannon, mathematics, physics, hybrid).
**Fix:** `--max-warnings 0` on lint; make the coverage step `exit 1`; reconcile 60 vs 80. **Effort: S** for the gates, **M** to pay down the backlog they expose.

#### M-5 · `SESSION_DIR` failure bypasses the error hierarchy and emits a garbled path
**Evidence (agent, live):** `SESSION_DIR=Z:\nonexistent` → client receives
`Error: ENOENT: no such file or directory, mkdir '\\?'` — a raw Node fs error with a **truncated path**, no mention of `SESSION_DIR`, no remediation hint. The stderr log directly above it has the correct path, so the mangling is in Windows long-path (`\\?\`) handling.
**Verified:** `StorageError` is defined in `src/utils/errors.ts` (one of **16** typed error classes) and referenced **0 times** in `src/session/`. A good pattern simply not wired to this path.
**Fix:** wrap `FileSessionStore.initialize` failures in `StorageError`; fix the long-path truncation. **Effort: S–M.**

#### M-6 · Three parallel mode definitions with no TS↔skill cross-check
**Evidence:** the TS `ThinkingMode` enum (34) and the skill layer's `test/schemas/*.json` (46) overlap on 34 shared modes. The 12 skill-only modes are intentional (`think-frameworks`). But `test_artifact_consistency.py` never references `src/` — it cross-checks skill artifacts against each other only.
**Impact:** a Zod validator field can change in `src/validation/validators/modes/` and nothing detects that `test/schemas/<mode>.json` has diverged.
**Fix:** generate JSON Schema from the Zod validators for the 34 shared modes and assert equality. **Effort: M.**

#### M-7 · npx launch path costs ~9× a local start
**Evidence (measured, n=4/5):** `npx -y deepthinking-mcp@9.2.0` → **3012.8 ms** (σ 440.2) vs `node dist/index.js` → **346.7 ms** (σ 29.9), both with a warm cache and no download.
**Assessment:** this is the *deliberate* consequence of the documented no-bundle decision (zod v4 cannot be flattened by esbuild). **Not a recommendation to reverse it** — quantified because it is the real per-cold-launch cost of that tradeoff: ~2.7 s.
**Fix:** none required. Revisit only if zod's bundling story changes. **Effort: n/a.**

### ✅ Verified clean (a clean category is a finding)

- **Export path traversal — genuinely well defended.** `resolveSandboxedOutputDir` (`src/export/file-exporter.ts:46`) resolves *before* comparing, then requires the prefix match. **10/10 live escape payloads rejected**: `../` and `..\` chains, absolute paths, `C:\Windows\Temp`, `\\?\C:\...`, `//./C:/...`, and mixed `reports/../../..`. Drive-relative `C:temp-escape` and the `....//` decoy correctly resolved *inside* the sandbox. Nothing escaped. *Untested: a pre-planted symlink under the sandbox root — no in-scope tool can create one.*
- **Prototype pollution — explicitly hardened.** `file-store.ts:544–593` builds with `Object.create(null)` and drops `__proto__`/`constructor`/`prototype` during the post-`JSON.parse` walk. Correctly placed and genuinely necessary. No YAML ingestion exists anywhere in `src/`.
- **Python render scripts — no injection.** Zero `shell=True`/`os.system`/`eval`/`exec`. `render-diagram.py` uses list-form `subprocess.run` with a 60 s timeout and a temp file. `render-html-dashboard.py` whitelists `mode` *before* the JS-context substitution (defeating a `</script>` breakout that `json.dumps` alone would not stop), `html.escape`s everything else, and fails loudly on unsubstituted tokens.
- **Dependencies:** `npm audit` → **0 vulnerabilities**. Tarball is exactly the 6-file allowlist.
- **Ordinary error handling:** structured Zod errors with field paths, no stack traces, no PII.
- **TypeScript rigor:** `strict`, `noUnusedLocals`, `noUnusedParameters`, `noImplicitReturns`, `noFallthroughCasesInSwitch` all genuinely enabled.
- **Version reporting:** `initialize` returns `serverInfo.version` matching the pin — a maintainer can confirm what a user runs.
- **Per-request performance:** 0.56–0.74 ms per tool call across 10 modes (n=200 each); dispatch is not a bottleneck.

## 5. Corrections to the agents

Three claims failed independent verification. Recorded because the corrections matter more than the originals.

**C-1 · "The server exposes 13 tools; `plugin.json`'s 14 is the outlier."** *(supportability agent)* — **Inverted.** A live handshake returns **14**. Ground truth: `jsonSchemas` holds 13, plus a legacy `deepthinking` tool registered separately at `src/index.ts:159`. `plugin.json` is *correct*; README/CLAUDE.md's "13" is stale. Relaying this unchecked would have sent a fix to the wrong file — and would have missed L-2 entirely.

**C-2 · "Unbounded session creation (DoS), HIGH."** *(security agent)* — **Overstated.** Sessions *are* LRU-bounded: `src/session/manager.ts:150`, `maxSize: 1000`. The agent's PoC created 120 sessions and inferred no limit; 120 < 1000, so the observation was consistent with a cap it never reached. Downgraded to M-1 (documented cap dead, real cap 10× higher). **The genuine unbounded vectors are per-session thought arrays (H-3) and free-text field size (H-2)** — both confirmed. Net: severity down, precision up.

**C-3 · "Lines of code 115,713, CLAUDE.md's ~102,000 is WRONG by 13%."** *(maintainability agent)* — **Not reproduced.** `src/*.ts` measures **103,847**; the documented ~102,000 is essentially right. The agent measured a wider scope. Removed from the drift list.

Everything else each agent reported was verified accurate — including several findings sharper than the brief anticipated (the `test_version_consistency.py` blind spot and the `docs:deps`/js-yaml double break were both unprompted discoveries).

## 6. Method and containment

Four read-only auditors ran concurrently on an idle machine (2–4% CPU, 36 GB free, sampled 3×). Each had a pre-launch baseline (process set, VSS shadows, free space per drive, scratch path) and a post-return sweep.

**Cleanup gate:** all four scratch directories deleted, **zero orphaned processes**, zero VSS shadows, free-space drift 0.04–0.05 GB (far under the 2 GB backstop). Three sweeps initially returned `Clean=False`; both causes were judged noise and recorded rather than acted on:
- `bash` PID 40392 — a transient harness shell, **already exited on re-check**. Acting on the first flag would have killed a still-running sibling agent's shell.
- `sppsvc` — Windows Software Protection Platform service, OS-owned.

Repo state verified clean before and after (`git status --porcelain` empty). The only repo mutation across the whole audit was `dist/` being regenerated from unchanged `src/` by a permitted build.

*Not covered:* symlink-based sandbox escape, corporate-proxy install behaviour, cross-OS test behaviour (Windows only; CI runs a 3-OS matrix), exhaustive prompt-injection review of all 14 tool descriptions, pairwise handler duplication analysis, and per-file distribution of the 357 `any` warnings.
